# ULisp (Underlying LISP)

**ULisp** は、Abdulaziz Ghuloum 氏の古典的論文 *"An Incremental Approach to Compiler Construction"* および植山類氏の *compilerbook* のインクリメンタル TDD 手法に基づき、Scheme サブセットから **x86-64 Linux 向けネイティブコード（GAS / ELF）** を出力する自己完結型セルフホスティングコンパイラです。

- **包括設計仕様書（正典）**: [DSN-33 (ULISP 包括設計仕様書)](../docs/designs/DSN-33-ulisp_underlying_x86_native_aot_compiler_architecture_specification.md)
- **開発者テクニカルリファレンス**: [ulisp/docs/README.md](docs/README.md)
  - [パイプライン・Nanopass 詳細仕様書](docs/pipeline_architecture.md)

## 1. 「A, I, U」三位一体アーキテクチャにおける位置づけ

```text
┌─────────────────────────────────────────────────────────────────┐
│ ALisp (Agent Lisp / DSN-32)       : AIエージェント安全保証層    │
├─────────────────────────────────────────────────────────────────┤
│ ILisp (Infrastructure / DSN-31)   : R7RS標準・推論・Python連携層│
├─────────────────────────────────────────────────────────────────┤
│ ULisp (Underlying Lisp / DSN-33)  : x86-64 ネイティブ金属直結層 │
└─────────────────────────────────────────────────────────────────┘
```

ULisp は将来的に **ILisp の「Backend B: Native AOT コンパイラ」** として結合され、ILisp/ALisp のコードを外部依存ゼロの単一 ELF バイナリへ直接コンパイルします。

## 4. ULisp と MLisp (JIT) のアーキテクチャ境界と分離方針

ULisp と MLisp は統合せず、**「役割と責務を厳格に分離したまま独立して発展させる」** 設計方針を採用しています。

### (1) 役割と責務の境界線
```text
┌────────────────────────────────────────────────────────┐
│  ULisp (Underlying Lisp): 静的 AOT コンパイラ基盤       │
│  - 役割: C言語コンパイラ (GCC) / RPython AOT 変換系に相当 │
│  - 性質: ステートレス、純粋関数型、決定論的             │
│  - 保証: セルフホスティング不動点（diff stage2 stage3 == 0）│
│  - 入力: S式 ──► 出力: x86-64 / ARM / C アセンブリ      │
└──────────────────────────┬─────────────────────────────┘
                           │ 単方向依存 (ULisp は MLisp に依存しない)
                           ▼
┌────────────────────────────────────────────────────────┐
│  MLisp (Meta Lisp): 動的 JIT 実行環境 / 言語 VM         │
│  - 役割: Python (PyPy) や Node.js 等のランタイム VM に相当│
│  - 性質: ステートフル、動的、投機的最適化               │
│  - 機能: mini-eval、メタトレーサ、PE、JITバッファ管理    │
│  - 入力: S式 ──► 出力: インプロセス即時実行とJIT加速   │
└────────────────────────────────────────────────────────┘
```

### (2) 厳格な依存関係ルール
- **`mlisp` -> `ulisp` (許可)**: MLisp が ULisp の標準ライブラリ（`lib/`）や Nanopass パス（00〜07）を読み取り専用で利用することは適格。
- **`ulisp` -> `mlisp` (厳格に禁止)**: ULisp のコード、Makefile、ビルドスクリプトは `mlisp/` に一切依存してはならない（逆依存 0 件の維持）。

### (3) 分離を維持する理由
- **セルフホスティング不動点保証の保護**: ULisp のコード規模を極小に保ち、動的 JIT の副作用やメモリ管理を混入させないことで、決定論的なセルフホスティング完全同一性（`diff == 0`）を永久に保証するため。
- **関心事の分離**: 静的 AOT コンパイラ（ステートレス）と動的 JIT 実行環境（ステートフル）の関心事を分離し、それぞれ独立したペースで最適化・機能拡張を推進するため。
