# [REQ-01] システム要求事項定義書 (System Requirements Specification - WHAT / WHY) — arxiv-security-papers

本ドキュメントは、「`arxiv-security-papers`」プロジェクトにおける**ビジネス目的（WHY）**および**システム要求事項（WHAT）**を定義する要求事項定義書です。具体的な実装方式・ソリューション・技術選定（HOW）は基本設計書 (`DSN-01`) および詳細設計書 (`DSN-02`) に分離・委ねます。

---

## 1. 背景と戦略目的 (Background & Strategic Objectives - WHY)

### 1.1 背景 (Background)
サイバーセキュリティ分野（`cs.CR`）の最新論文は日々大量に発表されており、脅威・脆弱性・防御技術の把握に膨大な調査コストを要しています。また、論文フォーマットの非標準性や言語の壁、AI エージェントと人間の双方からアクセス可能な統一的なインターフェースの欠如が課題となっています。

### 1.2 目標 (Strategic Objectives)
1. **即応的インテリジェンス化**: 世界中のセキュリティ論文を自動追跡し、調査コストを抜本的に低減する。
2. **標準化ナレッジ共有**: 非構造な論文テキストを再利用可能なオープン知識フォーマットへ標準化する。
3. **デュアルアクセス環境の提供**: 人間向けの直感的な視覚ポータルと、AI エージェント向けの標準相互運用プロトコルを同時に提供する。

---

## 2. 機能要求事項 (Functional Requirements - WHAT)

### REQ-FR-01: セキュリティ論文の連続追跡と原本保存要求
- **要求**: システムは、過去 160 日間に遡って全セキュリティ論文のメタデータ、要約、全文テキスト、および原本 PDF を自動取得・永続保存できなければならない。
- **目的**: 一次資料の完全なトレーサビリティと、後続の分析処理におけるデータの再利用性を担保するため。

### REQ-FR-02: 構造化ナレッジ標準化要求
- **要求**: システムは、収集した非構造な論文データをオープンかつ機械読取可能な統一ナレッジ形式にトランスフォームし、メタデータ（プロバナンス、著者、公開日時、信頼性アテストステーション）を付与できなければならない。
- **目的**: AI エージェントや分析ツールが知識を相互参照できる標準データ基盤を構築するため。

### REQ-FR-03: 5階層エグゼクティブサマリー生成要求
- **要求**: システムは、収集頻度・日次・月次・四半期・通期の 5 つの独立した時間軸で、100% 日本語化された構造化要約および比較表を自動集計・更新できなければならない。
- **目的**: 時間軸に応じたトレンドおよび重要論文を即座に把握可能にするため。

### REQ-FR-04: 高精度セマンティック検索 ＆ 専門用語拡張要求
- **要求**: システムは、14,000 件以上の累積論文群に対し、セキュリティ専門用語の表記揺れ・略称・日英同義語を自動補正・拡張した上で、関連度順に検索結果を提示できなければならない。
- **目的**: 検索漏れ（Recall低下）を防ぎ、日本語・英語問わず意図した論文へ即座に到達可能にするため。

### REQ-FR-05: AI エージェント相互運用プロトコル要求
- **要求**: システムは、外部の LLM や自律型 Security Agent が直接呼出可能な標準プロトコル経由で、論文検索、詳細取得、トレンド参照、脅威マップ逆引き機能を提供しなければならない。
- **目的**: AI エージェントエコシステムとのシームレスな統合を実現するため。

### REQ-FR-06: 直感型 Web ポータル ＆ ブックマーク可能 URL 要求
- **要求**: システムは、グラフィカルな Web 閲覧画面を提供し、URL クエリパラメータによる直感的な検索アクセスおよびブックマーク・URL 共有（検索状態の保存）を可能にしなければならない。
- **目的**: 利用者が環境を問わず即座に検索・分析・結果共有を行えるようにするため。

### REQ-FR-07: リッチドキュメント・動的図表レンダリング要求
- **要求**: Web ポータルは、構造化要約内の比較テーブルや動的なトレンド構造図を、ブラウザ上で直感的なグラフィカル表示として描画できなければならない。
- **目的**: 視覚的な理解を促進し、ドキュメントの解読効率を高めるため。

## 3. 非機能要求事項 (Non-Functional Requirements - WHAT)

### REQ-NFR-01: 可用性・自動フォールバック要求
- **要求**: 一次データソースの通信障害時においても、セカンダリソースへの自動切り替えにより、データ収集処理が継続動作しなければならない。
- **目標**: バッチパイプライン稼働率 99.9% 以上。

### REQ-NFR-02: 処理の冪等性・重複排除要求
- **要求**: 同一論文の重複処理を自動検出し、無駄なリソース消費や同一成果物の重複生成を防止しなければならない。
- **目標**: 複数回実行時における成果物の完全な整合性と冪等性の維持。

### REQ-NFR-03: トレーサビリティ・検証可能性要求
- **要求**: すべての生成サマリーおよび標準化ナレッジから、元となった一次データソース（Raw JSON/PDF）へ辿ることができるデータ系統（Lineage）を保持しなければならない。
- **目的**: 情報の真偽検証と根拠追跡を保証するため。

### REQ-NFR-04: 情報セキュリティ・アクセス境界ガード要求
- **要求**: システムは、意図しないファイルアクセスや機密情報（認証鍵、設定情報）の漏洩を物理的・論理的に遮断するアクセス境界ガードを備えなければならない。
- **目的**: セキュリティ脅威からシステムリソースを保護するため。

### REQ-NFR-05: 性能・レスポンス要求
- **要求**: Web ポータルにおける論文検索およびドキュメント表示の応答時間は、通常時 1.0 秒以内で完了しなければならない。
- **目的**: 快適な検索体験とストレスのない情報収集を保証するため。

### REQ-NFR-06: 品質管理・静的検証要求
- **要求**: システムに含まれるすべてのコード・ドキュメントは、構文エラー 0 件、不正リンク 0 件、および全単体テスト 100% PASS を常時満たさなければならない。
- **目的**: 継続的インテグレーションにおける高品質と安定性の維持。
